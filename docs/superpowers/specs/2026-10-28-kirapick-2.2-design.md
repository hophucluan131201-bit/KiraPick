# KiraPick 2.2 — scoring AIs, personal taste, AI updates, editions

Status: design approved section by section by the owner on 2026-10-28 (chat); this file is the written spec for review.

## 1. Intent

The owner (cosplay/street photographer) wants KiraPick's ranking to match their own eye better:
better general photo-quality AIs, an app that learns the owner's personal ("subjective") taste,
clearer explanations of every score, a tidier left panel, a manual "update AI models" feature,
and three installers (DirectML official, CUDA and OpenVINO betas).

Owner decisions (verbatim choices in chat):
- Learn from: Keep/Reject and stars in the app (main), client picks (light weight: "client picks are what fits
  the client, not always the best photo").
- Show two separate scores: **Kỹ thuật** (technical) and **Hợp gu bạn** (fits your taste).
- Models: direction B — OpenAI CLIP ViT-L/14 + LAION improved aesthetic predictor. The owner accepts the OpenAI
  model-card caveat ("deployed use out of scope") for this non-commercial app, with a disclaimer (like ArcFace).
- AI updates: user-initiated only, curated KiraPick catalogue, SHA-256 + digital signature, rollback.
- Versions: DirectML official **2.2.0**; CUDA beta **2.2.0a**; OpenVINO beta **2.2.0b**.

Unchanged invariants: originals never modified; no faked outputs (missing model/insufficient data = "not judged"
with the reason); analysis and normal use need no network; CPU fallback; licences documented.
Changed invariant: "100 % offline after installation" becomes "offline except the user-initiated, signed AI-model
update in ⚙ Tuỳ chọn". CLAUDE.md, README, TECHNICAL_SPEC notes and model-licenses.md are updated to say so.

## 2. New models

| Model | Purpose | Licence | Size (fp16 weights) |
|---|---|---|---|
| OpenAI CLIP ViT-L/14, image tower + projection | 768-d image embedding per photo | code MIT; model card: deployed use out of scope (owner accepted, disclaimer) | ≈ 600 MB |
| LAION improved aesthetic predictor `sac+logos+ava1-l14-linearMSE.pth` | aesthetic score 1..10 from the CLIP embedding | Apache-2.0 | < 4 MB |
| CLIP text embeddings of a fixed English prompt list (≈ 40 prompts) | explain taste, detect artistic styles | derived from CLIP (same caveat) | < 0.2 MB |

- Converted at build time (like `scripts/convert_topiq.py`): `scripts/convert_clip.py` downloads pinned weights,
  checks SHA-256, exports ONNX (static 1×3×224×224 input), checks ONNX vs PyTorch on several images
  (embedding cosine ≥ 0.999, LAION score |Δ| ≤ 0.01), writes sidecar SHA-256; `shrink_models.py` stores fp16 weights.
  The prompt embeddings are computed in the same script and saved as `clip_prompts_v1.npz`.
- Preprocessing exactly as CLIP/LAION trained: shorter side → 224 (bicubic), centre crop 224, CLIP mean/std.
  Embedding L2-normalised before the LAION head.
- Model manifest entries with purpose `quality_plus`; missing → the capability is shown as unavailable.

## 3. Pipeline and storage

- New resumable stage `clip` inside 📊 Phân tích ảnh (quality job, `STAGE_VERSION` 5), one inference per photo on
  the embedded/RAW preview (no full-res needed). GPU per session device rules (speed check, CPU fallback).
- Project DB (migration, additive): table `clip_embeddings(asset_id PK, model_version, vector BLOB fp16)`;
  `measurements.laion_mos REAL`; `measurements.style_tags TEXT` (JSON list of detected prompt tags with similarity).
- Scores are recomputable without re-running CLIP (embeddings stored, versions recorded).
- Timings added to `quality_timings_s`/self-test (`clip`, device).

## 4. Scores

**Kỹ thuật (0–100)** = existing rubric (focus, eyes, face, exposure, framing, aesthetic) with N/A redistribution.
The aesthetic part = mean of the available mapped TOPIQ and LAION values; each mapping range (low/high) is
calibrated on the owner's sample shoots and recorded with a profile version. Detail shows both raw numbers.

**Hợp gu bạn (0–100)** — personal taste model (section 5); "not judged" with the reason when not ready.

**Ranking for selection** = (1 − w)·Kỹ thuật + w·Hợp gu, w = 0.5 by default (⚙ setting, 0..1); w = 0 when taste
is not ready. Hard defects (eyes closed, focus < 30) cap the combined score at the technical score, **unless** an
artistic tag is present (intentional motion blur, low-key/silhouette, dreamy soft focus, …) **and** Hợp gu ≥ 70;
then the photo is labelled "ngoại lệ nghệ thuật". Burst diversity and per-subject ranking are unchanged.

## 5. Personal taste learning

- Learning store (global, local, schema v6, additive): `culling_feedback` gains `photo_key` (hash of session id +
  asset id; one row per photo, upserted when the decision changes), `source` ('app'|'client'), `label`
  (+1/−1), `weight`, `stars`, `clip` BLOB (fp16), `clip_version`, plus all technical parts already stored.
- Labels and weights: ★4–5 or ❤ → +1 × 1.5; ✓ Keep or ★3 → +1 × 1; ✗ Reject or ★1 → −1 × 1;
  client pick → +1 × 0.3; undecided / ★2 → not used. Rows with a different `clip_version` are ignored.
- Model: L2-regularised weighted logistic regression in numpy (no new dependency). Features: CLIP embedding
  (768) + standardised technical parts with missing-value flags. Trained in < 1 s at the start of 📊, when a
  session opens, and after every 20 new decisions; stored with its training count and version.
- Gate (never guess): needs ≥ 60 used decisions with ≥ 20 positive and ≥ 20 negative, and a 5-fold
  cross-validated weighted AUC ≥ 0.65 (folds split by shoot day so similar burst frames do not leak).
  Otherwise the UI says "Chưa đủ dữ liệu: n/60 lựa chọn" or "Chưa đoán được gu (độ khớp 0,58)".
- Output: probability × 100. Explanation: the 3 prompt concepts most aligned with the learnt weight vector
  ("bạn hay giữ ảnh ngược sáng"), the technical parts with the largest weights ("bạn hay loại ảnh nhắm mắt"),
  number of decisions and CV AUC. 🎓 dialog shows the same; "Quên" clears it as today.

## 6. UI

- Right panel "Phân tích AI": both scores; one bar + numeric value + reason text per criterion; reasons for
  N/A; aesthetic shows "TOPIQ x · LAION y"; taste line with decision count and AUC; main weakness; artistic
  exception line.
- Left panel: collapsible sections Thư mục / Lọc / Chủ thể (state remembered); Thư mục hidden when the session
  has one folder; filters as compact 2-column toggle buttons without their own scrollbar; subject list without
  horizontal scrolling (elided names with tooltip), 56 px avatars, photo count as a right-aligned badge, list takes
  the remaining height.
- ⚙ Tuỳ chọn: taste weight w; "Cập nhật mô hình AI…".
- Qt main thread never blocks (training and updates run in workers).

## 7. AI model updates (user-initiated, signed)

- Entry: ⚙ Tuỳ chọn → "Cập nhật mô hình AI…". Never automatic, no background checks.
- Confirmation dialog first: hosts contacted (github.com and its release download host), what is downloaded,
  that no photos/scores/personal data are sent. Only this module may open network connections; a unit test
  enforces that no other app module imports networking code, and the network-blocked self-test stays.
- Catalogue: `models-catalog.json` + `models-catalog.json.sig` published as assets of a dedicated KiraPick
  GitHub release (`models-catalog`). Signed with Ed25519 in CI (private key = GitHub Actions secret, set once by the
  owner following step-by-step instructions); public key embedded in the app. Library: `cryptography` (Apache-2.0/BSD).
- Each entry: model id, version, file URL(s), size, SHA-256, licence, minimum app version, `embedding_compatible`
  flag (false → affected stages re-run and affected learning rows ignored until re-recorded).
- Download into `data_dir()/models/staged/`, verify SHA-256, then activate atomically into
  `data_dir()/models/active/` (registry checks it before the bundled folder); previous version kept for
  "Quay lại bản trước". Interrupted downloads resume or are discarded; nothing half-written becomes active.
- Only models curated and tested by KiraPick appear in the catalogue (licence checked, thresholds recalibrated).

## 8. Editions and release order

1. Betas on `beta` (2.1.0b7, b8, …): (a) left panel + explanations; (b) CLIP + LAION + taste; (c) AI updates.
2. Official **2.2.0** DirectML once the owner finds the last beta fine (owner's release command already given).
3. **2.2.0a** CUDA and **2.2.0b** OpenVINO, same code, always published as pre-release, titled
   "KiraPick 2.2.0a – NVIDIA CUDA (beta)" / "KiraPick 2.2.0b – OpenVINO (beta)".
   - `scripts/build_windows.ps1 -Edition directml|cuda|openvino` with `packaging/requirements-<edition>.txt`;
     the edition is written into the app (shown in About/status bar and self-test).
   - Release workflow: edition chosen by a commit marker (`[release]`, `[release-cuda]`, `[release-openvino]`);
     non-DirectML editions always `--prerelease`.
   - CUDA installer exceeds GitHub's 2 GB per-asset limit as one zip: publish Setup.exe and its .bin slices
     (each < 2 GB) as separate assets plus the install guide.
   - OpenVINO: CPU device by default; the self-test reports OpenVINO vs plain CPU timings; if it is not faster the
     release notes say so.

## 9. Testing and evidence

- Unit: taste model (synthetic separable data → high AUC; random labels → gate closed; folds by day; weights;
  client pick weight); learning store migration v5→v6 and upsert; score combination, hard-defect cap and artistic
  exception; LAION/TOPIQ mapping; catalogue signature (valid, tampered, wrong key), SHA mismatch, atomic activation,
  rollback; only the updater imports networking code; project DB migration.
- Conversion checks (ONNX vs PyTorch) in the build; packaged self-test (network blocked) with CLIP timings/device.
- GUI tests offscreen for the new panels; the owner tests on Windows (we cannot run the Windows GUI here).
- No accuracy claims without measurement; LAION/TOPIQ mapping ranges and the taste gate are reported with the
  data they come from.

## 10. Added by the owner after review (2026-10-28: "mục số 6 thực hiện luôn")

- **Grid score badges:** each thumbnail shows "K 78 · G 85" (G only when taste is ready) and a short main-weakness
  icon; grid sort options "Điểm kỹ thuật", "Hợp gu", "Điểm xếp hạng".
- **Pairwise prompts ("Thích tấm nào hơn?"):** 🎓 menu → "So sánh ảnh"; shows two similar photos of the same
  subject (CLIP cosine ≥ 0.9, same burst/subject) whose ranking is closest; the answer is stored as one +1 and one
  −1 example with weight 0.5 each (source 'pair'). Never pops up on its own.
- **TOPIQ technical (KonIQ) and TOPIQ face (CGFIQA) models:** IQA-PyTorch code and weights are PolyForm
  Noncommercial 1.0.0 (same as the TOPIQ aesthetic model already approved); training datasets are research
  datasets → same disclaimer. Technical model adds a "chất lượng ảnh" signal to the focus/exposure explanation and
  rubric (weight taken from focus, recalibrated); face model adds "chất lượng mặt" to the face criterion for the
  lead subject's face crop. Both optional: missing → not judged.
- **Automatic AI-update check:** setting "Tự kiểm tra bản AI mới khi mở app" (off by default; the owner can turn
  it on). When on: at most once a day, after the window is shown, only the signed catalogue is fetched in a worker;
  if newer models exist a non-blocking notice offers the update dialog. Never downloads models by itself;
  silent when offline. CLAUDE.md wording: offline except user-enabled/user-started signed AI updates.
- **Release:** after implementation and tests, publish 2.2.0 (official), 2.2.0a and 2.2.0b (pre-releases) — the
  owner's explicit release command.
